# 全流程体验检查

日期：2026-10-05（Asia/Taipei）
依据：[设计约束](DESIGN_BRIEF.md)。隔离环境：http://127.0.0.1:3310。

## 已复现并修复的问题

1. 表单校验失败后输入被清空。注册输入不同确认密码，提交后用户名、昵称和密码全部丢失。证据：`screenshots/before-register-error-input.png`、`screenshots/before-register-error-result.png`；录像：`../../dogfood-output/register-error.webm`。根因是 React Action 返回错误状态时仍触发原生 reset。
2. 报名→登录→注册丢失 next 目标，注册后固定返回工作概览；完善竞技资料后也缺少返回原赛事的入口。
3. 手机端全局管理入口隐藏，个人栏目横向隐藏且没有滚动提示。证据：`screenshots/before-workspace-mobile-375.png`。
4. 管理员没有角色对应的下一步，仍被引导补齐选手资料；裁判、解说也被呈现为必须完成竞技资料。证据同上。
5. 运营概览将长设置表单和日常任务混排，缺少从审核到赛果的步骤入口。
6. 身份审核将历史已审记录与待处理混排，无状态与角色筛选。
7. 赛果录入的可选 BP 默认展开，与核心阵容同权重；手机三列挤压 BP 目标。两半场的 datalist ID 重复。
8. 首页无公开赛事时缺少空态；已结束赛事仍被称为“当前开放赛事”，登录用户被引导重新注册。

## 修复与验证

| 问题 | 调整 | 验证 |
|---|---|---|
| 校验错误清空输入 | Action 表单统一使用原生 reset 监听保留输入，统一成功/错误反馈；正常提交仍走原服务器 Action | 注册与登录错误回归；赛果重复选手校验失败后地图、阵容保留，可修正并保存 |
| 报名上下文丢失 | 登录、注册、个人资料返回均保留安全校验后的站内 next；切换赛事时保留角色 | 解说注册后返回原赛事与身份；两名选手完善资料后返回报名 |
| 手机入口不可发现 | 管理入口保持可见；个人工作台用带标签的原生栏目选择器；窄屏登录态标识精简 | 320/375/768/1280 宽度管理入口、栏目跳转、无横向溢出 |
| 角色引导不合理 | 管理员、赛事管理者、待邀请、待指派、待审核按角色和状态提示下一步；竞技资料明确仅选手报名需要 | 管理员直接进入管理；解说不需要先完成选手资料 |
| 运营层次混乱 | 日常运营按审核→名单→排赛→赛果排列；设置、封面折叠为次级操作；结束赛事保留展开的重新开启入口 | 三尺寸运营概览复核；核心排赛、赛果业务链通过 |
| 审核混排 | 有待审核时默认只看待审核；状态和角色使用链接筛选，归档只读时仍可查询历史 | 解说批准后在已通过+解说筛选可见；无数据时显示清晰空态 |
| 赛果编辑负担 | 每局展示地图与积分预览；BP 无数据时折叠，有数据时展开；手机目标单独占一行；保存栏随滚动可见；datalist 唯一 | 积分 10:0 预览、错误修正、草稿保存及公开发布回归；三尺寸与手机细节复核 |
| 公开页面文案/层次 | 按报名、进行、结束分组；首页按实际状态显示赛事，登录用户进入工作台；补充无公开赛事空态 | 公开页面响应式、导航和无障碍回归；上线后验证实际空态 |

体验链覆盖：匿名浏览→登录/注册→资料→身份申请/审核→建队审批→邀请/接受→公开队伍→通知；管理员创建赛事→阶段/晋级/排赛→指派→结构化赛果错误修正/保存/发布→公开赛程与比赛档案。数据库事务和权限规则沿用现有回归。测试业务写入只发生在隔离数据库。

原有庄园档案主题、字体、配色与公开数据权限保持；未引入依赖。浏览器未出现运行异常。公开页与个人工作台的 axe 检查要求 critical/serious 违规为零；该自动检查不能替代完整人工无障碍认证。
